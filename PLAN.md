# Plan: Hard-gated factual verification for team-build deliverables
_Locked via grill — by Claude + Matt_

## Goal
Kill the dominant failure mode (A1: shipping a deliverable where Claude answered from vanilla Pokémon knowledge without consulting Delta data) by moving verification out of Claude's own generation context and into two things that cannot share its prior: a deterministic linter that **hard-blocks the docx/pdf export via a harness hook**, and a fresh, clean-context verifier sub-agent that adversarially re-checks the semantic claims a script can't parse. The existing §7.5 self-review fails precisely because it is Claude reviewing Claude in the same "ship it" context with the same vanilla prior; this plan replaces the mechanical half of §7.5 with code and the judgment half with an independent agent.

## Approach

1. **Build `tools/lint_team.py`** — a deterministic, dependency-light checker that takes a `teams/<file>.md` path and exits nonzero with a readable report on any violation. It parses the **6-row team table** at the top of the deliverable (`| Pokemon | Item | Ability | Moves | Role |`), which is the structured, reliable artifact (the `.md` has no Pokepaste block). **Hard checks are scoped to the team table** (the shipped sets); replacement-option sets get best-effort WARN-level checks only. Checks, all sourced from files, none from model memory:
   - **Species resolution via an alias map (not naive rules).** Filenames are inconsistent (`mega-flygon.json` *and* `gengar-mega.json`), and the banlist uses display forms (`Mega Gengar`, `Raichu-Mega-Y`). Build a single canonical alias map from: `data/mons/` filename stems, each file's `species.displayName`, and the canonical forms parsed from the banlist. Resolve every table name through this map. **An unresolvable species is itself a HARD FAIL** (catches A2). The map must be unit-tested against the real `data/mons/` filename list.
   - **Legal moves.** Every move in the Moves column must appear in that species' `legalMoves[]`. A move present in `_curated`/team-builder but absent from `legalMoves` is a HARD FAIL — unless it is on the structured data-gap allowlist `data/lint_allowlists.json` (`{species, move, reason}` entries; JSON, not parsed from `mod_days.md` prose).
   - **Ability legality (pre-Mega convention).** The team table + Pokepaste name the holder but list its **pre-Mega ability** (per `deliverable-spec.md`; e.g. Slaughtermaus lists Vorpal, the doc explains the Mega→Reap swap in prose). The linter validates each table Ability against the **base-form** `species.abilities`; Mega-named holders resolve to their base form's ability set for this check. Documented post-Mega abilities live on an exception allowlist in `data/lint_allowlists.json`. Wrong custom abilities are part of the A1 failure class, so a mismatch is a HARD FAIL.
   - **Ban check (parsed, not substring-grep).** `notes/banlist.md` is the **sole machine-parsed ban source**. Parse only its *active banned-bullet lines* into canonical ids, then **exact-match** resolved species/form ids against that set. Never substring-grep the whole file — that false-fails legal notes like "Iron Sentinel is legal" and false-misses form aliases. `reference/season meta changes.txt` is unstructured prose and is **human reference only — never parsed by the linter**. A banned mon is a HARD FAIL.
   - **Item legality.** Build a checked `data/item_locks.json` mapping species-locked items (Z-crystals, Mega stones) → permitted species, generated from known mappings (team-builder raw text is too inconsistent to trust live). Known mismatch = HARD FAIL; an item not in the map = WARN (don't false-block on incomplete coverage).
   - **Tera line.** HARD FAIL only on actual set syntax: regex anchored `^\s*Tera\s?(Type)?\s*:`. Must **not** match `Terapagos-ATOM` or prose mentions of Tera.
   - **Doc hygiene greps** (mechanical subset of §7.5): em/en-dash, customer-language, internal-data-ref phrasings — each must be zero hits (HARD FAIL).
   - **Phantom mons (WARN-only, section-aware).** In identity/role/wincon sections only, flag any non-team Delta species name as probable swapped-slot residue. Never a hard block (Kingambit etc. legitimately appear in matchup/replacement prose). Prefer a tracked prior-slot name list when one is available.
   - **Verifier completion marker (hash-bound).** For Full-tier exports, a sidecar `teams/<name>.verify.md` (the verifier sub-agent's findings + Claude's resolutions, kept OUT of the client docx) must exist, be non-empty, and carry a `source-sha256:` header equal to the SHA-256 of the SRC `.md` being exported. The linter recomputes the SRC hash and HARD FAILs if the sidecar is missing, empty, or hash-mismatched — so a stale sidecar from an older draft cannot satisfy the gate after the `.md` changes.
   - **Output:** grouped HARD FAIL vs WARN; nonzero exit iff any HARD FAIL. Denials appended to `teams/.lint-denials.log` for observability.

2. **Primary gate: lint runs INSIDE `tools/md_to_docx_pdf.py`, fail-closed.** At the top of the converter, before reading/converting, it runs the same `lint_team.py` checks on the exact `SRC` it is about to convert and **aborts (nonzero exit) on any HARD FAIL**, writing the report to stdout + the denial log. This closes the TOCTOU window — a compound command can't lint-then-modify-then-export, because the converter re-lints the file it actually opens. Conversion itself is gated. **`tools/md_to_docx_pdf.py` is the single canonical export path**; `/build` must call only it (stated explicitly in `build.md`).

3. **Close the alternate-exporter bypass (non-destructive).** The repo has ~30 historical one-off exporters in `teams/` (`build_*.js`, `build_*.py`, `_build*.py`) that would each bypass a converter-only gate. These are the user's past build records — **not deleted or moved** (they stay as history). Instead, the `PreToolUse` hook (below) uses a concrete deny rule: **deny any Bash command whose text contains a `.docx` or `.pdf` output target unless the command invokes `tools/md_to_docx_pdf.py`.** This catches the legacy `teams/build_*`/`_build*` scripts *and* ad-hoc evasions (`python -c`, `node -e`, renamed scripts, copied output paths), with a message directing to the canonical wrapper. The legacy scripts are frozen for reference, blocked from producing *new* exports.

4. **`PreToolUse` hook** in `.claude/settings.json` as the early/breadth layer. It (a) runs `lint_team.py` before a canonical-wrapper export and denies on nonzero exit, and (b) denies non-canonical exporter invocations per step 3. It extracts the source `.md` failing *closed* (blocking) if it can't reliably parse the arg, given the workspace path contains a space. The settings writer **merges into any existing `settings.json` keys** rather than overwriting; exact hook JSON specified in implementation. The converter-internal gate (step 2) is the guarantee; the hook is breadth + early signal.

5. **Add the verifier sub-agent as a mandatory `/build` step** (new step, e.g. §7.6, after §7.5). Spawn a fresh `Explore`/general agent with a clean context and an explicit instruction: *"You have no reliable vanilla Pokémon knowledge for this mod. Every Delta-specific factual claim (typing, ability behavior, move effect, speed tier, coverage multiplier, KO claim) must be verifiable against a cited file in `data/` or `notes/`, or it is a finding. Read only the deliverable + the data files. Refute, don't rubber-stamp."* It returns a findings list. Claude resolves or dismisses each finding **in writing in the sidecar `teams/<name>.verify.md`** before delivery. Mandatory-but-advisory: not an exit-code gate on its *verdict* (it's nondeterministic), but its *completion* is enforced — the linter HARD FAILs the export if the sidecar is missing/empty (step 1 marker).

6. **Trim `build.md` §7.5** to remove the now-automated mechanical greps (legal moves, dash/phrasing greps, phantom-mon grep, Tera check, ban check) and point them at the linter as the source of truth, keeping only the judgment-heavy items (speed math, coverage/damage reasoning, mechanic attribution) for human/agent review. Avoids two divergent copies of the same checklist.

7. **Tests + observability (built with the linter, not deferred).** Add `tools/tests/` pytest fixtures: one clean team that must pass, and several poisoned teams that must each trip a specific check (illegal move, banned mon, wrong ability, Tera line, dash, unresolvable species, item mismatch), plus alias-map edge cases (`gengar-mega` vs `mega-flygon`) and ban-alias cases (`Mega Gengar`). **Verifier-sidecar fixtures: missing, empty, stale-hash, and matching-hash** (only the last passes). The alias map and ban-bullet parser get direct unit tests against the live `data/mons/` + `notes/banlist.md`. Hook/converter denials append to `teams/.lint-denials.log`.

8. **Backlog (phase 2, not built now): `tools/lookup.py`** — a "RAG-lite" CLI (`python tools/lookup.py "tinkaton-gamma typing"`) that resolves naming gotchas and greps the correct source file, addressing A3/A2 once A1 is handled. Explicitly **not** a vector DB / embedding index — that infra isn't worth maintaining against a fast-moving meta. Documented as a backlog item only.

## Key decisions & tradeoffs
- **Verification lives outside the builder's context, not as a better checklist.** A self-review shares the prior that produced the error; the deterministic script has no prior and the sub-agent has a clean one. This is the core thesis.
- **Hard block on the script, advisory-but-mandatory on the sub-agent.** Deterministic code is safe to make a wall; an LLM verifier is not (false positives would stall correct builds). Split accordingly.
- **Two distinct guarantees: converter lint vs hook.** Converter-internal lint closes the lint-then-modify-then-export TOCTOU window *on the canonical path* (it re-lints the exact file it opens). The PreToolUse hook is what blocks *alternate* exporters (legacy scripts, `python -c`, etc.). Neither alone is sufficient: the converter can't stop a different exporter, and the hook's static command-text match can't see post-lint file mutation. Together they cover both. You can't force a model to look mid-generation; you *can* refuse to produce the artifact until ground-truth checks pass.
- **Parse the team table, not a Pokepaste; hard checks scoped to the 6 shipped sets.** The `.md` deliverable has no paste block; the table is the structured artifact actually present. Replacement-option sets are WARN-only.
- **Resolve species through a tested alias map, never naive lowercase-hyphen rules.** Real filenames are inconsistent (`gengar-mega` vs `mega-flygon`); the map is the linter's defense against its own A2 risk, and an unresolvable name fails hard rather than silently skipping a check.
- **Ban check parses canonical ids and exact-matches.** Substring-grepping the banlist false-fails "X is legal" notes and false-misses form aliases.
- **WARN vs HARD FAIL is deliberate.** Deterministic, high-confidence checks (legal moves, abilities, bans, Tera, dashes, unresolvable species) hard-block. Heuristic checks (phantom-mon residue, unmapped items) only warn, to avoid stalling a correct build on a false positive.
- **Cut Obsidian; backlog RAG-lite as a CLI.** Neither touches A1. Obsidian is human-navigation polish with ~zero agent benefit and the notes are already clean markdown. RAG-lite is a grep-wrapper, not embeddings.

## Risks / open questions
- **Parser brittleness.** If the team-table markdown format drifts (extra columns, missing pipes, multi-line cells), the linter could false-fail or false-pass. Mitigation: fail loud and explicit when the table can't be parsed (treat unparseable-table as HARD FAIL), never pass silently.
- **Alias map is the linter's own A2 risk.** A wrong map mis-resolves and either false-fails or skips a real check. Mitigated by unit-testing it against the live `data/mons/` filename list and failing hard on any unresolvable name.
- **`notes/banlist.md` / `mod_days.md` format dependence.** The linter parses human-written notes; if their structure changes the checks silently weaken. Mitigation: assert the expected banned-section anchor exists and HARD FAIL the lint (not the build silently) if the parser finds no recognizable structure.
- **`item_locks.json` staleness.** A hand-built item→species map drifts as new Z/mega items appear. Mitigated by treating unmapped items as WARN, not silent pass, so new items surface for the human.
- **Converter-internal lint changes `md_to_docx_pdf.py` behavior** — it now exits nonzero on bad input. Any existing wrapper/automation calling it must handle a nonzero exit. Mitigation: document the new contract; the denial log makes failures visible.
- **Sub-agent cost/latency** added to every 300k build. Acceptable per the human; scoped to the Full tier.
- **Resolved:** the gate applies to the 300k Full tier only — the 60k Basic tier is review-only and produces no docx, so the converter (and thus the gate) never runs there. Out of scope by construction.

## Out of scope
- Vector-DB / embedding RAG (explicitly rejected; CLI grep-wrapper backlogged instead).
- Obsidian / any human-navigation tooling (cut).
- Fixing B (stale data — handled by the user's seasonal update cadence) and C (fabrication under genuine no-source uncertainty — rare).
- Auto-*fixing* deliverables; the system blocks and reports, it does not rewrite sets itself.
- Re-architecting the lookup chains in CLAUDE.md (they're already correct; the problem is enforcement, not documentation).
